# Portal SEO and mobile performance audit — 28 September 2026

## Scope

This update adds dedicated Angular, React, and Vue guides, crawlable navigation,
documentation breadcrumbs, and regression checks. It does not publish a new SDK,
guarantee search rankings, or resolve all performance/accessibility findings.

## Priority follow-up work

1. **Premium main-thread work and layout stability.** The report found 18 long
   tasks, 8.3 seconds of main-thread work, and 4.4 seconds of JavaScript execution.
   The shift diagnostic identifies the site footer moving (CLS 0.584); this is
   the affected element, not proof that footer CSS is the root cause. Profile the
   page's demo initialization and prerender-to-client transition, then evaluate
   deferred below-the-fold demos and stable preview dimensions. Preserve usable
   previews and crawlable feature descriptions. Retest before claiming a fix.
2. **Documentation loading.** Investigate the 3.8-second LCP and approximately
   96 KiB of unused JavaScript. Measure the LCP element and shared guide-data
   chunks before changing lazy loading or hydration. Do not enable hydration
   blindly around DOM-mutating table components.
3. **Accessibility.** Home reports contrast and table-header associations;
   Premium reports contrast and incompatible ARIA roles. Inspect the failing
   elements and perform keyboard/screen-reader checks. A score alone is not an
   accessibility certification.
4. **Repeat measurements.** Compare multiple mobile runs after deployment, then
   use Search Console/CrUX field data when sufficient traffic exists. Lighthouse
   SEO 100 checks basic discoverability only; it does not confirm indexing,
   structured-data rich-result eligibility, ranking, or visitor acquisition.

## Automated release coverage

- Exact local and remote examples compile for Angular strict templates, React
  TSX, and Vue SFCs against the published 1.0.0 wrappers and core 1.1.1.
- The remote-data recipe validates responses and forwards cancellation. It
  requires an application-owned backend; this audit does not certify a backend
  implementation or remote authentication flow.
- Unit tests cover guide content, navigation, and breadcrumb structured data.
- Production build checks unique metadata, canonical URLs, complete sitemap
  coverage, documentation breadcrumbs, and internal links/anchors/images.
- Link checks inspect built HTML and redirects. They do not crawl external sites
  or prove that a JavaScript interaction works.

## Dependency hygiene

Angular runtime/compiler packages were updated from 22.1.3 to 22.1.4 for
[GHSA-v3p8-whq6-r5jg](https://github.com/advisories/GHSA-v3p8-whq6-r5jg) and
[GHSA-f6mr-pjwc-34m4](https://github.com/advisories/GHSA-f6mr-pjwc-34m4).
These are server-rendering advisories; the public portal is deployed as static
GitHub Pages, not an exposed Angular rendering server. After the patch,
`npm audit --omit=dev` reported zero known vulnerabilities. The full audit still
reported five affected development packages: `fast-uri` (high), `hono`, `qs`,
`vitest`, and `@vitest/mocker` (moderate). Those toolchain updates remain separate
follow-up work; this patch is not a claim that every dependency is vulnerability-free.
